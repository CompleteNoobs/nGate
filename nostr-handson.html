Nostr Hands-On

A bare-metal Nostr learning page. One file, no install, no client opinions, no follow lists, no profile rendering. Every WebSocket message is logged in section 5 and mirrored to the browser console (open DevTools / F12). Read the source — it is the tutorial.

1. Identity — load a private key

Paste your nsec1... or 64-char hex private key. The key stays in this tab's memory only — it's never sent to any server, written to disk, or kept after you close the tab.
⚠ Use a disposable key. The privkey lives in plain JS memory while this tab is open. Browser extensions, page bugs, or future you forgetting which tab is which can all expose it. For real Nostr usage, use a NIP-07 extension (nos2x / Alby) — see the wiki.
No key loaded.

2. Relays — open WebSockets

Pick which relays to use. Click Connect on each one. Status flips disconnected → connecting → open. Read-only relays don't need your key. Write relays need your pubkey on the relay's whitelist (for your private relays, that means you set them up correctly in config.toml).
A "Connect" failure is almost always: bad URL, relay offline, or your network blocking outbound 443. Check the system log entry for the WebSocket error.

3. Compose — sign and publish events

Build a Nostr event, sign it with your loaded key, and broadcast to every open relay. The signed event is logged in section 5 — check the JSON to see id (sha256 of canonical fields), sig (schnorr), tags, etc.
Goes to every relay currently in the open state.
NIP-04: end-to-end encrypted. Relays see the ciphertext + the recipient's pubkey, not the body.
NIP-04 is the original DM scheme — old, deprecated for new clients (NIP-17 is the modern one), but transparent and supported everywhere. Good for learning. Do not use it as your main DM transport long-term.

4. Subscribe — ask relays for events

A subscription is a REQ message with one or more filter objects. Relays send matching stored events, then EOSE (end of stored events), then keep streaming new matches in real time until you CLOSE.
Filters are JSON predicates: {kinds:[1], authors:[hex]}, {kinds:[4], "#p":[my-hex]}, etc. Relays AND the conditions inside a filter, OR across multiple filters in one REQ.

5. Event Log — every WebSocket message in/out

Click any JSON block to expand/collapse. Browser console (F12) gets the same data — useful for searching with Ctrl+F. Outgoing in orange, incoming in blue, system in grey, errors in red.
